# 溢出属性训练摆烂 — 根因分析（v4：归因定谳，进入解药 A/B）

> 症状（小黑板已知问题文档）：「溢出属性训练摆烂：例如溢出智时不训练，选择休息。」
> 基线：上游 xulai1001/umaai-rs master @ e8f6f263（本仓 master 为压缩镜像）
> 用户指路（09-12 原话，来源级①）：「他觉得训练都溢出了不能提高评分，想办法，比如不是光看评分
> 还得看别的一些指标……不要比赛回合后状态硬编码……现在这些都是表面现象。」

## 归因定谳（bench v2，7 build × 10 seed × 2 臂 = 140 局，CI 内解析）

```
A-preset: mean_score=64338.3 | races/game 强制=12.00 自选=0.33 | rests/game 守门标=1.81 打分=0.01 异常=2.27
```

1. **比赛**：12.00/game 全是 `career_races` 目标赛程强制（umaDB `races` 字段，用户完全正确）；
   策略自选比赛仅 **0.33/game** —— 「校准漂移→过度比赛」结论作废（已撤回）。
2. **休息**：4.08/game，**全部来自体力硬守门**（vital<40 → 强制休息）。
   「异常」2.27 = 守门触发后 recovery_guard 重算覆盖了 breakdown（丢了「守门」字样），
   本质仍是守门；**纯打分选休息 = 0.01/game ≈ 零**。
3. **守门误杀样本（实锤）**：
   - turn=13 vital≈29：休息 85 分 vs **智训练 583 分·失败率 5%·体力+5**；
   - turn=23 vital≈37：休息 62 分 vs **耐训练 525 分·失败率 20%**。
   守门的本意是「防失败率崩盘」，但它只看体力一个代理数，不看失败率、体力增量这些
   打分层已经算出来的指标。

## 深度定性（对「表面现象」的回答）

摆烂不是某个罚分项（S1 reserve 重复收费=真缺陷但聚合≈−67 分噪声级）也不是比赛问题。
结构病是：**决策链里存在「单指标一票否决」层（体力守门），凌驾于多指标打分层之上**。
- 低体力 → 无条件休息：失败率 5% 的智力位（体力+5）和失败率 20% 的耐位（525 分）一起被否决；
- 属性溢出 → 分数边际=0 时，打分层对训练的其余产出（诀窍槽进度→面经济、设施等级成长、
  羁绊→彩圈、剧本 PT 档位）没有计价语言——这是同一病根的另一张脸（用户真机案例）。
- 禁止的修法：给比赛回合后状态开特判（硬编码）；正确的修法：**让守门查它本意要查的指标**。

## 解药与 A/B（bench v4，七臂）

| 臂 | 配置 | 性质 |
|---|---|---|
| A | preset 原样 | 对照 |
| C/D | `wisf25` / `wisf35`（EXP-006c 智力位豁免，现成开关） | 纯配置 |
| E/F | `grf15` / `grf25`（patch 0002：任一训练位失败率≤N 且体力增量≥0 → 放行打分层） | 补丁，通用非特判 |
| G/H | wisf+grf 组合 | 补丁 |

patch 0002 语义：默认 `0.0`=关闭（逐位不变）；eval 只在低体力分支内算（守门惰性契约保留）；
`wisdom_vital_floor` 保留为本修复的特例。CI bench job 运行期 `git apply patches/*.patch`
（不提交回分支；apply 失败=红，防静默漂移）。

## 结果与后续判定

- 若 E/F 把 rests/game 显著压低且分数 ≥ A → 守门让位多指标打分成立，preset 建议开 grf；
- 剩余休息（若有）再看体力真崩盘（vital<25）是否合理；
- 溢出场景的「非分数产出计价」（诀窍进度/等级成长）= 下一张 patch（0003），
  等守门数据落地后再动，避免一次混两个变量。
