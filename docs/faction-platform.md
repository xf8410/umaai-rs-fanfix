# 项目纲领 v3：玩家+维护者语义版（主定义与流程）

> 一句话纲领：**我们是自己用这套自动训练的玩家，顺手维护了一个 fork。玩法=数据党：每个改动带开关、红测试、同卡组对照数据；数据说话、老板（也就是玩家本人）拍板；成熟的修复一律提 PR 回上游。**
> 不搞重写流派，不碰模拟层事实，不把手机端搞坏。

## 0. 双重身份（一切规则的来源）

- **玩家身份**：手机上要练出好马。→ 所以默认行为必须永远可预期：没拍板的改动 = 不存在（开关默认关）。
- **维护者身份**：fork 里修上游的错、测自己的方案。→ 所以一切修改按仓库规矩走：分支、flag、CI、对照、PR。
- 两身份冲突时，玩家优先。这条排他性优先级就是全部纪律的根。

## 1. 圈子里的几种人（原 40K 谱系 → 玩家/仓库语境的真实对应）

| 流派 | 干法 | 我们怎么评价 |
|---|---|---|
| 纯用户（issue 党） | 发现 bug 只在上游开 issue，代码一行不碰 | 太被动，自己的手机端等不起 |
| **fork 纪律派（← 我们）** | 改动=flag+红测试+CI 对照数据，证据齐了 owner merge，默认关=与上游逐位一致 | 正规维护路径 |
| 数据党/理论计算派（← 我们对 bug 的姿态） | 不质疑代码所有权，用模拟器和日志证明「这个数算重了/算反了」 | 我们的红测试+同种子 A/B 就是这套 |
| 回馈上游者（contributor） | 修好的补丁提 PR 给原作者合并，让 fix 进主线 | **对上游的路线：让正统的手颁布改革** |
| 重写流派 | 「策略层太烂，全部推倒」 | **红线：结果没人能预测** |
| 焦土派 | 「评分代码不行，删掉重来」 | **红线** |
| 换仓库跑路 | 弃坑换引擎 | 项目边界，不碰 |

## 2. 主定义（纲领牌）

**改动六步，一步不省：triage 定性 → 开分支装 flag → 先写复现红测试 → CI 同卡组对照 → owner 拍板 merge → 成熟提上游 PR。**
底线一条：手机端训练如常，玩家感觉不到维护者存在，直到数据说话。

## 3. 治「无头苍蝇」的 triage 桌：新现象先问归哪类

| 类别 | 白话 | 现成例子 | 管线 |
|---|---|---|---|
| ① 账算错（真 bug） | 逻辑错，不是口味问题 | 属性已满：溢出已被截断一次，「预留位罚分」又按整笔收 → 双份收费 | 纠错 patch + 复现测试钉死 → **0001 走完全程，等拍板** |
| ② 没建模（漏了机制） | 游戏会涨上限（Y2+20/Y3+40/超面+100），估值不知道 | 剩余空间的期权价值该随行数和剩余次数变化 | 建模 patch → **0004 排队** |
| ③ 参数失配（口味/平衡） | 方向或力度问题，只有数据能裁 | 体力单价越后期越贵（Y3 5.2/点），可第三年失败率−100%、友人回 48-80、有马+40、URA+20/回合——应该更便宜 | token 矩阵对照 → **0003 在测** |

每个改动过六关的细则：
1. **triage**：先归类再动手。归完类管线是现成的，防止拿到现象就改代码。
2. **装 flag**：默认关＝与上游逐位一致。这是玩家身份的抵押物。
3. **红测试＝复现证据**：先把「bug 现在会发作」写成测试，红着挂 CI 上，比任何描述都有说服力（也是将来 PR 里的 selling point）。
4. **同卡组对照**：同 seed、同 build，开/关各跑 N 把。**看行为指标**（训练中局数、「该练却休息」次数），整局总分对小修不敏感——0001 实测 ±0.1% 就是噪声。
5. **owner 拍板**：数据呈上，三个章：merge 转正 / 挂起留档 / revert。盖章的人是玩家本人。
6. **提上游**：证据链（issue 复现 + 红测试 + 对照数据 + 逐位回退保证）打包成 PR。我们的存在不必被知道，fix 进主线才算赢。

## 4. 当前看板（仓库视角）

- **0001 满位双收修正**：flag（reserve_clamp）+ 红测试 + 140 局对照全部交付。数据=中性不亏（−0.1%），价值=评分分解不再虚掉千分、与 policy 层「为拿 PT 练满位是正当行为」注释矛盾修正。**状态：待 owner 拍板**（上轮你选了「先挂起，转打 0003」）。
- **0003 体力定价分年（vcurve）**：flag 已装（Y1 4.0/Y2 3.5/Y3 2.5，默认关逐位不变），四路对照在 CI 跑：base / 只开0001 / 只开0003 / 双开（验两 flag 正交）。
- **0004 上限抬升期权建模**：triage 完毕（第②类），待 0003 出数后立项。
- **PT 偏好口径**：上游自带 `Selection::Pt` 开关，第③类捡现成——零 patch 成本，排 0004 后面。
- 设备版本核实：**撤下**（那是部署问题不是仓库问题，此前已裁定）。

## 5. 红线四条（哪类都不得越）

1. **体力门限 40：不动。** 玩家两次确认门限本身是对的——保安不是刺客。这是「玩家优先」原则的直接运用。
2. 没拍板前，默认行为与上游逐位一致（flag 纪律，CI 可验证）。
3. **评分表、失败率公式=模拟层事实**，是上游从游戏客户端扒出来的真相，不是观点——碰它们不是修 bug，是造假数据。我们只动策略层。
4. 上游自己 CI 挂的地方：如实标注、不修不藏不背锅（libtests 红=基线问题，跟我们无关的记录在案）。
