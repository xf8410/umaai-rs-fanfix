# 项目纲领（游戏大白话版）：我们这帮人按什么路子改游戏 AI

> 一句话纲领：**上游是官服，我们是一支「小改动先上测试服、跑对数据再转正、转正稳了就递给官服采纳」的 mod 队。**
> 不搞删档重来，不许把手机端搞坏。

## 1. 圈子里就这几种玩法，各自一句话

| 玩法 | 干的是啥 | 我们怎么评价 |
|---|---|---|
| 原教旨 vanilla 玩家 | 发现 bug 也不动手改，只在论坛发帖骂官服 | 太被动，手机端等不起 |
| **测试服党（← 我们）** | 每个改动带个开关：默认关=跟官服一模一样，开了才生效；对局数据好看才转正 | 稳，可回头 |
| 一键全洗点党 | 天赋树全推倒重来，赌一把大的 | **红线：结果没人预测得了** |
| 删号重练党 | 「这套评分代码太烂，全部重写」 | **红线** |
| 「数值坏了」反馈党（← 我们对 bug 的姿态） | 不推翻系统，就指着某一处说：这里算重了/算反了，给你看录屏和数据 | 修完还能递官服领采纳 |
| 递官服党（← 对上游的路线） | 把改好的 fix 提交给官服，让更新公告里写它的名字 | 比当私服之王划算 |
| 换游戏 | 引擎不要了，去玩别的 | 项目边界，不碰 |

## 2. 主定义（纲领牌，钉在门口）

**新改动五步走，一步不能省：定性 → 装开关 → 写红测试 → 同卡组对局数据 → 老板拍板转正 → 成熟递官服。**
底线一条：手机端主人训练如常，感觉不到我们存在，直到我们拿出数据。

## 3. 治「无头苍蝇」的登记处：新问题进来先问归哪类

| 类别 | 白话 | 现成例子 | 管线 |
|---|---|---|---|
| ① 算钱的逻辑错了 | 账算重了/算漏了 | 属性满了，溢出已被裁掉一次，「预留位置费」又按整笔收一遍（双份收费） | 纠错补丁+红测试钉死 → **0001 干完** |
| ② 系统没考虑新机制 | 数值没跟着版本走 | 上限会随年份涨（Y2+20、Y3+40、超面+100），估值还当它永远不变 | 建模补丁 → **0004 排队** |
| ③ 数值要调平衡 | 方向或力度不对 | 体力「单价」越到后期越贵（Y3 每点 5.2）——可第三年失败率归零、友人回 48-80、有马+40，明明应该更便宜 | 参数矩阵对局测试 → **0003 在测** |

每个改动过五关：
1. **装开关**：默认关＝和官服逐位一样。没装开关就谈转正=洗点党行为，打回。
2. **红测试=录屏**：先把「这个 bug 现在会发作」写成测试，红着就是证据。
3. **同卡组对局**：同一手牌、同种子，开/关各跑 N 把。看行为数据（训练中局数、"该练却去休息"次数），**别只盯总分**——小修小补总分本来不动（0001 实测：±0.1% 是噪声）。
4. **老板拍板**：数据呈上来，转正 / 挂起 / 回退，只有这三个章。
5. **递官服**：证据链齐活就提 PR 上游——让正统的手颁布这个 fix。

## 4. 当前议程牌

- **0001 预留位置费双收**：五关走完四关，就差老板盖章。对局数据：不亏不赚（−0.1%），价值在评分不再虚掉一千多分、和官服注释自相矛盾的修复。暂挂起（你上轮裁的）。
- **0003 第三年体力降价**：开关装好（vcurve：Y1 4.0→Y2 3.5→Y3 2.5），四路对局在测试服跑（官服原版 / 只开0001 / 只开0003 / 两个都开，验证不互相打架）。
- **0004 上限上涨提前看**：排队立项（第②类）。
- **PT 偏好搜索档**：官服自带现成旋钮（MCTS `Selection::Pt`），第③类，捡起来就能测。
- 设备版本核实：撤下（那是部署的事，不算改动）。

## 5. 红线四条（归哪类都不得越）

1. **体力门限 40：不动。** 老板两次确认门限本身是对的——门是保安，不是刺客。
2. 没转正前，所有默认行为跟官服逐位一致。
3. 评分表、失败率公式这些模拟事实不许碰——那不是改 bug，是改服务器。
4. 官服自己测试挂的地方：如实标注不修不藏（那是官服自己的 bug，不是我们的战场）。

> **彩蛋对照（战锤原典名，给设定党）**：测试服党=桑彩派 Xanthites（激进派里的温和派）；「数值坏了」反馈党=大叛教时代的修正主义者 Revisionists；递官服党=伊瑟莱安圈（廷内改革，借正统的手颁新法）；洗点党=单一至高派；删号党=盖勒净化派；换游戏=投混沌/润泰伦。党纲骨架不变，只是换成人话。
